# 弱网模拟器

电脑上运行的 HTTP/HTTPS 代理，手机通过 USB 把系统代理指向它。参数在网页控制台里拖动即时生效，
适合在同一网络条件下对比不同 App，支持同时连接多台 Android 手机。单文件，无需安装任何运行环境。

| 系统 | 文件 |
| --- | --- |
| Windows（绝大多数电脑） | `weaknet-windows-amd64.exe` |
| Windows ARM 笔记本 | `weaknet-windows-arm64.exe` |
| macOS Apple 芯片 | `weaknet-macos-arm64` |
| macOS Intel | `weaknet-macos-amd64` |

## 使用

1. 手机用 USB 连电脑，打开开发者选项里的 USB 调试并允许这台电脑。
2. 电脑需要能找到 adb：装了 Android Studio / platform-tools 即可；也可以把 `adb.exe`（以及同目录的
   `AdbWinApi.dll`、`AdbWinUsbApi.dll`）和本程序放在同一个文件夹。
3. 双击运行（macOS 在终端执行 `./weaknet-macos-arm64`，首次可能需要在"系统设置 > 隐私与安全性"里允许）。
   浏览器会自动打开控制台 http://127.0.0.1:8899 。
4. 在"手机"里对要测试的手机点"启用弱网"，再点"强制重连"，让已打开的 App 改走代理。
5. 切换档位或拖动参数，对比不同 App 的表现。
6. 结束时点"退出并恢复手机"，或直接关闭程序窗口，已启用的手机会自动恢复正常网络。

## 控制台

- 默认“实时工作台”分为设备操作和观测内容两部分，观测范围与流量概况合并展示，曲线按需展开；实时流量与请求事件单列排列。点击包名或域名可直接筛选，包名 / 域名和操作按钮同行显示。
- 实时工作台内可勾选多台目标手机，共用一个 App 包名和一组操作按钮，执行清空并启动、清空数据、重启 Wi-Fi、启用 / 关闭弱网；选中手机有忙碌或离线设备时禁用操作；批量清空前一次确认全部目标，逐台报告提交结果，实际执行结果见工具事件。作用范围、黑名单开关及黑白名单编辑也在同页；黑白名单各占一行，直接保存 / 撤销 / 复制，条目菜单可逐项删除。
- 档位和正常 / 卡死 / 断开控制始终固定在顶部，可直接展开参数，用数值或滑块调整带宽、延迟等，无需切页；所有页面共用这一套网络控件，配置页不再重复展示。顶部只保留实时工作台、连接历史和 ADB 日志三个入口，记住上次打开的页签和筛选条件；请求事件直接在工作台查看，默认跟随观测手机、App 和域名；可在更多筛选中关闭跟随，独立查看工具事件或其他请求。设备状态及测试方案收进「设置」。
- 顶部“暂停自动刷新”只冻结监控、事件及历史的自动显示更新，后台采集继续，设备状态和配置继续更新；恢复时展示最新数据。
- 支持复制域名、App 包名、手机序列号、连接完整详情和本页历史。事件支持单条复制脱敏 URL / 整条事件、复制筛选结果和导出 TXT。
  浏览器不允许写入剪贴板时会提供已选中的文本供手动复制。URL 查询参数仍为 `REDACTED`，不能用来直接重放请求。
- 黑白名单支持删除标签、自动去重和冲突提示。未保存的编辑会作为浏览器草稿保留，失焦、定时刷新、切换页签和重新打开页面不会覆盖；
  保存后才生效，可用“撤销草稿”恢复服务端配置。实时流量中的名单快捷操作会连同已有草稿一起保存。
- 独立“ADB 日志”页签支持多手机 Logcat 采集（main / system / crash）、按手机 / App 包名 / 最低级别 / 关键词筛选、暂停显示、单条或筛选结果复制及 TXT 导出；切页和关闭弱网不停止采集，USB 中断后自动重试，可单独停止所选或全部手机。最多保留最近 2000 条，清空只清本工具缓存；复制和导出按采集顺序，单条超过 8 KB 会截断。
- 参数修改会合并提交，保存失败保留待提交内容并提供重试；服务断开时显示错误提示，自动重试后恢复。

### 测试方案

“设置”中可命名保存当前参数、网络状态和黑白名单（含编辑草稿），应用前会展示影响范围并确认。
方案仅保存在当前浏览器，可导出 / 导入 JSON 迁移；导入会校验参数和名单，同名方案确认后替换，不会自动应用。
命令行启动参数仍决定每次启动时的初始配置，浏览器方案需要手动应用。

### 弱网参数

- 档位：不限速 / 4G / 3G / 弱网 / 2G/EDGE / 极弱网
- 参数：下行、上行带宽（按 kbps 输入，旁边同时显示换算后的 KB/s，和实时流量表的单位一致）、单程延迟、抖动、丢包率、每连接窗口
- 网络状态：正常 / 卡死（连接挂住，像信号极差）/ 断开（所有连接立刻断掉）
- 作用范围（哪些域名走弱网，名单都包含子域名）：

  | 黑名单开关 | 走弱网的域名 |
  | --- | --- |
  | 关 | 所有域名，白名单除外 |
  | 开 | 只有黑名单内的域名，白名单除外 |

  - 白名单优先级最高：同时在两个名单中时按白名单处理，不走弱网。
  - 不走弱网的域名直连、不限速，也不受"卡死/断开"影响，在流量表里标为"直连"。
  - 开关开启但黑名单为空时，不会限制任何域名。
  - 例：只测自家 App，打开开关，黑名单填 `yallajalsat.com,yallajalsat.live`；
    想让某些系统或 SDK 流量不受影响，把它们加进白名单。
- 监控：每台手机的下行速度、排队时长、按 App 和域名分组的流量。"排队 KB"是已到电脑、还在弱网队列里等着发给手机的数据，
  排得越多，长连接回包等得越久（等待时间 ≈ 排队总量 ÷ 下行带宽）。

## 按 App 分类

启用弱网时，程序会自动把一个小的中转程序推送到手机 `/data/local/tmp/wnrelay` 并运行（adb shell 身份，无需 root）。
App 的连接先到中转程序，它查出连接所属的 UID，电脑端再用 `pm list packages -U` 换成包名。于是：

- 流量表按 App 分组，每个 App 下列出它访问的域名；分组行上有"+黑名单""+白名单"快捷按钮。
- 黑名单、白名单可以直接填包名（如 `com.yalla.yallajalsat`），只限制或豁免这个 App 的全部流量，
  包括它用到的第三方 SDK、CDN 域名；也可以和域名混填。
- 设备卡片上显示"按 App 分类"；中转程序启动失败（如不支持的 CPU 架构）时自动退回"直连模式"，弱网照常可用，只是无法区分 App。
- 共享 UID 的系统应用会显示为"包名 (+N)"；UID 无法识别时显示为 `uid:xxxx` 或"未识别"。
- 关闭弱网或退出时中转程序随之结束；拔掉 USB 时它也会自动退出。
- USB 断开再连上（包括数据线接触不良导致的自动重连）后，会自动恢复这台手机的弱网，不需要手动重新启用。
  断开期间手机上的代理仍指向电脑，手机会暂时上不了网；重新连上后若 2 分钟内一直恢复失败，会清除手机代理并提示手动重新启用。

## 清空 App 存储

测试"首次启动"时不用再手动去系统设置里清数据：在"清空 App 存储"卡片选择手机、填写包名
（默认 `com.yalla.yallajalsat`，下拉列出连接历史里见过的包名），点"清空数据"或"清空数据并启动"。

- 先 `am force-stop` 再 `pm clear`，相当于全新安装：登录状态、缓存、配置都会清除，操作前会弹确认框。
- "清空数据并启动"会接着冷启动 App，方便直接观察首次启动的流量和连接。
- 包名只允许合法字符（字母、数字、下划线、点），防止拼进手机 shell 命令时被注入。
- 命令行：`curl -X POST 127.0.0.1:8899/api/device/<序列号>/clear -d '{"pkg":"com.yalla.yallajalsat","launch":true}'`

## 筛选与连接历史

- 顶部筛选栏可按手机、App（下拉列出见过的所有包名及累计流量）、域名关键字筛选，手机和 App 条件用于曲线、实时流量和连接历史；域名条件只用于实时流量和连接历史。
  选了 App 后，曲线和"下行 KB/s"只显示该 App 的流量，排队、活动连接和丢包停顿仍为整机统计；实时流量表和连接历史里点"只看它"或 App 名也能快速筛选。
- 实时流量按 手机 → App → 域名 分组，多台手机时每台一组。
- 连接历史记录每个连接的开始时间、手机、App、域名、上下行字节、耗时、状态（进行中/完成/失败/断网拒绝）和是否走弱网，
  进行中的连接字节数实时更新；顶部汇总连接数、总流量、失败数、平均耗时。
- 历史支持状态（含全部失败）、弱网 / 直连、开始时间范围筛选；每页 100 条，可以向前翻阅及回到最新。
  翻阅更早记录时停止历史自动更新，新增连接不会把后续页挤动；顶部汇总和 CSV 导出始终覆盖全部匹配记录。
- 点击域名或“详情”查看完整手机序列号、包名、端口和错误信息，并可复制。历史保留最近 20 万条，程序退出后清空；
  “导出筛选结果 CSV”导出当前筛选下的全部记录（Excel 可直接打开）。

## 请求地址事件

- “事件”显示资源（MP4 / SVGA / 图片 / ZIP 等）的 URL、HTTP 接口地址和请求方法，可按类型、URL、App 或手机关键词筛选。
- 请求事件显示“请求中 / 请求完成 / 请求失败 / 请求失败（超时）”标签，可按状态筛选；类型和来源收进更多筛选。选定 App 后，事件正文不重复包名；查看全部 App 时可点击包名标签筛选。复制和 TXT 导出仍包含完整包名、当前状态与原因，同一事件原位更新。
  明文 HTTP 在首个响应实际传输到客户端后完成，HTTP 4xx / 5xx、响应截断、连接失败和主动断开标为失败；实际观测到超时才标记超时，卡死模式不会凭计时猜测失败。
  未启用解密时，HTTPS 仅显示“连接中 / 隧道已结束”或连接失败，不能据此判断加密接口成功；App 地址日志没有响应信息，显示“结果未知”。
- `[代理]` 表示模拟器实际收到的请求：明文 HTTP 显示当前连接首个请求的地址；未解密的 HTTPS CONNECT 隧道只显示域名和端口；启用下方的 HTTPS 解密后，可显示每次请求的完整脱敏路径和响应状态。
- `[App 日志]` 表示通过 USB 读取 App 已有的请求日志，补充 HTTPS 完整路径。不安装 CA、不解密 TLS，也不改动 App 请求。
  这类事件不代表请求一定经过代理、已占用带宽或已经下载完成；缓存命中、失败重试等仍需结合流量和 App 日志判断。
  目前支持 `JschatLog` 下的 `Domain` 最终地址 / 切域重试、`JalsatHttp_Url`、`JschatHttp_Url`，以及标准 `OkHttp` 请求行。
  Domain 和 API 紧邻输出的相同地址会合并；现有业务日志没有 HTTP 方法时留空，不猜测 GET / POST。
  App 关闭日志、未输出支持的请求日志或原生网络栈没有日志时，无法获得完整路径。采集随设备启用弱网开始，关闭弱网、USB 断开或退出时结束。
- 普通隧道及 App 日志不记录请求头或请求体；已解密请求可查看下方说明中的请求响应详情。URL 中的用户名、密码、fragment 会移除，所有查询参数值替换为 `REDACTED`，保留域名、路径和参数名方便排查。
- 页面保留最近 300 条事件，程序退出后清空；终端也会输出相同的脱敏事件。如自行重定向终端输出，请按本地调试日志管理。

## 固定 CA 与 HTTPS 解密

打开“设置 → HTTPS 解密 · 固定 CA”，下载 CA 证书与 Android 配置。CA 第一次启动时自动生成，后续启动复用，不随程序更新改变。默认目录：macOS `~/Library/Application Support/weaknet`，Windows `%AppData%/weaknet`；可通过 `-data-dir` 指定。`ca.pem` 同时含证书和私钥（权限 0600），备份或迁移时需保留；不要提交到 Git 或发给手机。下载接口只导出公开证书，设置中可核对 SHA-256 指纹和有效期。已有身份损坏或过期时启动会报错，不会自动替换。

Android 调试包配置：

1. 将下载的公开证书保存为 `app/src/debug/res/raw/weaknet_ca.crt`。
2. 将下载的配置保存为 `app/src/debug/res/xml/network_security_config.xml`。已有网络安全配置时，将其中的 `debug-overrides` 合并进去，保留原有规则。
3. 在调试 Manifest 的 `<application>` 设置 `android:networkSecurityConfig="@xml/network_security_config"`。确保运行的是 `android:debuggable="true"` 的调试构建。

```xml
<network-security-config>
    <debug-overrides>
        <trust-anchors>
            <certificates src="@raw/weaknet_ca" />
        </trust-anchors>
    </debug-overrides>
</network-security-config>
```

手机信任配置准备好后，在“实时工作台 → 请求事件”管理解密域名。输入域名并点“添加并解密”，或在实时流量 / 请求事件中点击“+HTTPS 解密”，会保存域名并启用解密。域名标签支持筛选和移除，批量编辑提供“保存并重连 / 撤销草稿”。切换开关、增删范围会重连解密方式变化的 HTTPS 连接，无关域名、明文 HTTP 和已按相同方式解密的连接不受影响。未保存的域名草稿不会被轮询覆盖，保存失败保留草稿。

设置持久保存在 `https.json`。域名包含其子域名，支持 IP，不接受 URL、端口或通配符。默认关闭，其他 HTTPS 仍走原来的隧道。请求事件也提供“+黑名单 / +白名单”操作，可按“HTTPS 已解密”筛选。

解密后显示每次 HTTPS 请求的脱敏地址、请求中 / 完成 / 失败 / 超时及 HTTP 状态码；4xx / 5xx 标记失败。已解密事件提供“请求 / 响应”详情，查看并复制请求头、请求体、响应头、响应体、HTTP 状态和耗时；打开时实时更新，选中文本时暂停覆盖正文。Authorization、Cookie、Token 等敏感头脱敏，正文按原内容预览。详情仅保留在本机内存，最多 100 个请求，每侧正文最多 64 KB，头部最多 16 KB；超出显示截断提示，转发数据不截断。文本、JSON、gzip / deflate 可预览；二进制仅显示大小，WebSocket 仅保留握手头。正文通过详情接口按需读取，不放入状态轮询或终端日志；程序退出即清空。

弱网限制作用在客户端 TLS 字节流上，白名单与黑名单规则保持生效。支持 HTTP/1.1 和 WebSocket 转发；客户端协商 HTTP/1.1，上游可使用 HTTP/2，仍校验上游证书。忽略系统代理的网络栈、QUIC 不在此代理范围。`debug-overrides` 仅在调试构建生效，自定义 OkHttp 等证书固定机制也需在调试构建中适配；信任错误会显示在请求事件中。

## 多台手机

- 只有点了"启用弱网"的手机才走弱网，其他手机不受影响。
- 每台启用的手机有独立的代理端口（8888、8889……）和独立带宽，互不抢占；参数所有手机共用。
- 手机显示"已有其他代理"时，说明系统代理不是本程序设的（比如上次异常退出残留），可点"清除代理"。

## 命令行参数

```
-preset weak        启动档位：unlimited|4g|3g|weak|edge|bad
-device             只连了一台手机时，启动后直接启用
-serial A,B         启动后直接启用这些手机
-blacklist a.com,b.com  黑名单（同时打开黑名单开关）：只有这些域名走弱网
-whitelist a.com,b.com  白名单：这些域名永远不走弱网
-port 8888          代理起始端口
-ui-port 8899       控制台端口
-dns 223.5.5.5      解析域名用的 DNS（绕开本机代理软件的 fake-ip），-dns "" 用系统解析
-adb PATH           指定 adb 路径
-no-browser         不自动打开浏览器
```

接口也可以用命令行调：

```bash
curl -X POST 127.0.0.1:8899/api/preset/3g
curl -X POST 127.0.0.1:8899/api/config -d '{"down_kbps":300,"delay_ms":250,"loss_pct":2}'
curl -X POST 127.0.0.1:8899/api/config -d '{"outage":"stall"}'   # "" | "stall" | "reset"
curl -X POST 127.0.0.1:8899/api/config -d '{"blacklist_on":true,"blacklist":"yallajalsat.com,yallajalsat.live"}'
curl -X POST 127.0.0.1:8899/api/config -d '{"whitelist":"googleapis.com"}'
curl -X POST 127.0.0.1:8899/api/device/<序列号>/on               # on | off | reconnect
```

## 局限

- 只影响走系统 HTTP 代理的流量。UDP（RTC 音视频、QUIC）和忽略系统代理的 App（部分游戏、Flutter 自带网络栈的 App）不受影响。
- "丢包"用 TCP 重传超时的停顿模拟，代理在 TCP 之上无法真正丢包。
- 程序被强制结束（任务管理器杀进程、电脑断电）时来不及恢复手机，手机会上不了网：重新运行后点"清除代理"，
  或执行 `adb -s <序列号> shell settings put global http_proxy :0`。
- 弱网下冷启动 App 可能卡在初始化，建议先在正常网络下打开 App 再启用弱网。
- 启用期间系统联网检测可能显示 WiFi"无法访问互联网"，不影响测试。
- 模拟器到 App 之间多了"模拟器 → adb → 手机端中转程序 → App"几段，各段都有缓冲。App 靠"读得慢"给下载限速时，
  数据会先灌进这些缓冲，模拟器上看到的流量会比 App 实际读取的多、也比真实网络多。中转程序和模拟器已把自己
  这一侧的 socket 缓冲压到 32 KB，但 adb 内部的缓冲无法控制，验证限速时以 App 自己的日志为准。
